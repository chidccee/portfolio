# Область и тестовые предположения

## В области тестирования

- форма авторизации;
- каталог товаров;
- сортировка каталога;
- карточки товаров;
- корзина;
- форма данных покупателя;
- экран обзора заказа;
- завершение заказа;
- навигация и выход из системы.

## Вне области тестирования

- безопасность и нагрузка;
- серверное API и база данных;
- интеграция с реальной оплатой и доставкой;
- кросс-браузерное и мобильное тестирование;
- внешние ссылки на социальные сети;
- доступность по WCAG.

## Тестовые предположения

Поскольку формальная спецификация не предоставлена, ожидаемое поведение определялось по интерфейсу и типовым правилам интернет-магазинов.

1. Пользователь с корректными данными должен попасть в каталог.
2. Пользователь `locked_out_user` не должен получить доступ и должен увидеть понятное сообщение.
3. Каталог должен содержать уникальные названия, описания, цены и соответствующие товару изображения.
4. Сортировка должна изменять порядок всех карточек согласно выбранному критерию.
5. Добавленный товар должен появляться в корзине, а счётчик — соответствовать количеству товаров.
6. Удалённый товар должен исчезать из корзины и счётчика.
7. Имя, фамилия и почтовый индекс обязательны для продолжения оформления.
8. Экран обзора заказа должен показывать выбранные товары и корректные суммы.
9. После успешного завершения заказа пользователь должен увидеть подтверждение.
10. После выхода защищённые страницы не должны оставаться доступными через обычную навигацию.

## Критерии начала и завершения

Начало тестирования возможно, если сайт доступен, форма входа открывается, а тестовые учётные данные опубликованы на странице приложения.

Тестирование считается завершённым после выполнения приоритетных сценариев авторизации, каталога, корзины и оформления заказа, а также регистрации обнаруженных дефектов.
